# Standalone artwork routing

## What changed

The retired imageproxy URL was generated by Jive, not by the station service:
`SlimServer.fetchArtwork` and, independently, `ImageViewer.requestImage` sent
public HTTP(S) artwork to Logitech regardless of its image format. HTTP failures
could also leave an in-flight cache marker, preventing a subsequent retry.
See [the source investigation](LEGACY_IMAGE_PROXY_RESEARCH.md) for original
firmware file/function/line references.

This implementation deliberately supersedes that report's proposed general
image-processing service: **there is no raster decoder, resizer, re-encoder,
new raster cache, image database, daemon or new dependency.**

## Flow

```text
Jive SlimServer / ImageViewer
             |
       Base Artwork.route (also getStandaloneArtworkURL service)
             |
             +-- LMS ID / relative resource / local URL -> existing handling
             +-- known SVG extension -> existing local /api/image/render
             +-- public raster or unknown type -> sbproxy artwork route
                                      |
                                      +-- PNG/JPEG -> stream bytes unchanged
                                      +-- final image/svg+xml -> local 302
                                                 |
                                         /api/image/render
                                                 |
                                existing bounded download + svgpngrenderer
                                                 |
                                      PNG response / existing SVG cache
```

Jive's own HTTP client and Surface decoder retain their existing compressed
image buffering and raster decode behavior. “Streaming” here means **sbproxy
does not accumulate or decode the image**; it does not mean Jive itself has a
streaming image decoder.

### Shared Lua adapter

`applet/Artwork.lua` is usable immediately during Jive artwork processing,
without waiting for the Base applet to instantiate. It has no network calls.
Other applets may use `getStandaloneArtworkURL(url, width, height)`. The existing
`getStandaloneImageURL` remains SVG-specific and backward compatible.

The helper preserves percent escapes and signed query strings without decoding
them. Cover IDs, relative LMS paths, local numeric addresses, localhost,
unqualified hostnames and `.local`/`.lan` resources retain their original handling.
Unknown hostnames resolving privately cannot use the public proxy. Public IPv6
fetching is not supported by the current public-address policy.

Known numeric-loopback `/http/` and `/https/` wrappers are normalized **once** into
the artwork route, rather than nested. This is necessary for existing applets
that wrap HTTPS before publishing metadata: MIME-only SVG must not bypass
conversion. Arbitrary local service paths and already-normalized artwork/render
URLs are not rewritten. Known SVG URLs with query strings use the existing
renderer directly. SVG dimensions are bounded to its existing 16–512 range;
smaller Jive requests use the 16-pixel minimum.

### Proxy interfaces

- `GET|HEAD /http/<host>/<path>`: new plain HTTP transport.
- `GET|HEAD /https/<host>/<path>`: existing HTTPS compatibility transport.
- `GET|HEAD /artwork/<width>/<height>/<web-port>/<http|https>/<host>/<path>`:
  streaming artwork transport with SVG MIME dispatch.

The artwork route always enforces public IPv4 destinations and ports 80/443,
including actual sockets opened after DNS resolution and every redirect. The
new plain HTTP route uses the same restrictions. Neither can be used to fetch
private metadata services through redirects. Existing HTTPS compatibility and
opt-in `X-SB-Public-Fetch` behavior remain available; the TLS certificate
verification compatibility policy is unchanged. This is not authenticated TLS.

Curl follows relative, multi-hop and cross-scheme redirects internally, with
three redirects, a three-second connection timeout and eight-second total
transfer timeout on the new public routes. Final status, relevant response
headers, Content-Type, Content-Length and Range behavior are preserved. Public
routes do not forward caller cookies or Authorization. Existing worker limits
remain eight proxy workers and four concurrent requests per Jive SlimServer;
there is no new permanent worker pool.

When the final response has MIME type `image/svg+xml`, the artwork route emits
a local 302 to the configured web port's existing renderer endpoint and stops
receiving the source body. No raw SVG is sent to Jive. The renderer independently
validates and fetches the original URL, preserving its existing security and
resource limits. This may fetch a source twice on a conversion miss; it avoids
new buffering/IPC/conversion machinery in the proxy. It also means origins must
return a reproducible response on that second request. Incorrect MIME types
without an SVG extension cannot reliably be identified by this adapter.

The SVG cache is retained: it avoids expensive repeat conversions and already
has limits. Removing it would increase CPU without simplifying this routing
change materially. No PNG/JPEG persistent cache or maintenance work is added.
Existing SVG behavior when persistent storage is unavailable is unchanged.

## Firmware integration and request state

`scripts/patch-squeezeplay-artwork.sh` defaults to both firmware files and also
accepts one file for offline testing. It creates a backup, checks known source
anchors, writes through a temporary file, and installs atomically per file.
Unknown layouts fail safely rather than overwriting their implementation.
Files with no retired proxy producer are left unchanged. There is no global
SqueezeNetwork hostname or HTTP-client replacement.

Small adapters use the shared helper at the existing external-artwork branches;
ImageViewer additionally classifies HTTPS before the old HTTP-only test. LMS
resize placeholders, contributor artwork handling and other firmware-specific
branches are preserved. The sink adapter retains the original firmware body
behind an early block return rather than deleting adjacent source code.

The shared sink owns one request slot and accepts one terminal result. It:

- Clears failed/timeout/decode-error in-flight markers so later calls can retry.
- Caches compressed bytes only after a successful Surface decode.
- Ignores duplicate terminal callbacks and stale generations.
- Retires active generations and icon waiters on cancel-all without falsely
  freeing still-active sockets; terminal callbacks release their slots later.
- Retains useful existing in-memory cache and deduplication behavior.

An individual icon cancellation detaches that icon, allowing a shared request to
complete and populate the cache for other consumers. No automatic retry loop or
polling was added. Subsequent artwork requests perform the retry.

Installation/startup invokes the patcher for both paths. Source edits affect the
next Jive process, not Lua modules already loaded in memory. Review the patch log
and arrange a user-approved Jive restart after installation if needed. No device
was deployed to or restarted while implementing this change.

## Validation performed

Passed:

- Lua 5.1 helper routing and lifecycle tests: public HTTP/HTTPS PNG/JPEG, SVG,
  query strings, local/LMS resources, already-wrapped URLs, failure/retry,
  duplicate/stale callbacks, decode failure and cancellation/retry.
- Shell patch tests: backups, idempotence, both producers, modern no-op and
  unknown-source rejection.
- Actual captured firmware copies and the available upstream checkout: both
  patched artwork functions executed against routing assertions. Full-file
  host syntax checks normalize Jive's `!=` extension for stock Lua; shipped
  firmware syntax is not rewritten. The upstream fixture's HTTPS-aware viewer
  and contributor-artwork branch are preserved. This checkout is **not claimed
  to be a verified 9.x firmware release**; a separately identified 9.x fixture
  was not available.
- ARM-emulated proxy integration: HTTP/HTTPS, both cross-scheme directions,
  relative/multiple redirects, loops, 403/404, timeout, HEAD, Range/header
  filtering, MIME-only SVG with encoded queries, invalid targets, and a 4.9 MiB
  response streamed unchanged and checked by SHA-256.
- Shipped ARM proxy security tests: private destinations rejected for existing
  guarded HTTPS, new HTTP and artwork routes. Test-only origin allowances are
  compiled into a separate executable and are absent from shipped binaries.
- Existing native SVG CLI tests and SVG HTTP integration, including transparency,
  invalid input, size limits, caching and renderer failure/deadline recovery.
- Existing remote HTTP, browser pairing, station management and native Now
  Playing unit tests.
- `scripts/build-arm.sh`: all six binaries built as stripped static ARM EABI5
  executables without dynamic dependencies. NanoSVG retains its existing
  signedness warning; host build also reports an unrelated existing unchecked
  `fgets` warning in system-info code.

The unrelated frontend process-monitor test could not run: Node is unavailable
in the current shell/WSL environment. A full CTest run was not performed because
CMake is unavailable in WSL; the relevant native and integration tests were run
directly. Hardware memory, audio continuity and visual correctness are **not
validated for this implementation yet**.

Reproduce relevant tests in a configured host CMake build with CTest, or run the
shell/Lua scripts directly. `test_firmware_artwork.lua` accepts repository root,
patched SlimServer fixture path and patched ImageViewer fixture path. Firmware
fixtures remain local rather than publishing device files. The proxy integration
test takes the dedicated `sbproxy_test` executable; the guard test takes the
production `sbproxy`. ARM tests can prefix these executable arguments with
`qemu-arm`. Build target binaries with `sh scripts/build-arm.sh`.

- `applet/Artwork.lua`: new routing and request-state helper.
- `applet/ImageRender.lua`: expose existing configured web-port lookup.
- `applet/StandaloneBaseApplet.lua`, `StandaloneBaseMeta.lua`: optional shared
  artwork service and both-file patch invocation.

- `scripts/patch-squeezeplay-artwork.sh`: verified adapters for both Jive paths.
- `scripts/deploy_dist.py`: invoke both-file patching when deployment is later
  explicitly requested; this change itself performs no deployment.
- `packaging/build-package.sh`, `build-package.ps1`: include the helper.
- `tests/CMakeLists.txt`, `tests/comet/test_artwork_patch.sh`,
  `tests/images/test_artwork.lua`, `test_firmware_artwork.lua`,
  `test_artwork_proxy.py`, `test_proxy_guard.py`: tests/registration.

Existing uncommitted SVG implementation files are a prerequisite, not a new
raster-processing feature added by this change.

## Real-device acceptance procedure (pending, not executed)

1. Explicitly approve packaging/deployment and a Jive restart separately. Back up
   firmware and applet files using the normal deployment procedure. Verify both
   patch results in the Base artwork-patch log; unknown-source errors must be
   resolved against that firmware's source, not bypassed.
2. During audio playback, exercise RFM, Jazz Radio, Radio Classique and NRJ Hits
   using the installed station configuration. Include known PNG, JPEG, SVG and
   extensionless-SVG sources. Confirm visible alpha, correct display dimensions
   for SVG, and ordinary raster rendering. Repeat in stock Now Playing, menus
   and ImageViewer. Also test Spotify native artwork and Qobuz audio regression.
3. Inspect proxy/Jive diagnostics: requests should use loopback artwork/render
   routes and public origins, never Logitech imageproxy. Verify HTTP-to-HTTPS,
   HTTPS-to-HTTP and relative redirects. Do not publish origin query tokens.
4. Switch stations rapidly at least 30 times. Test an unavailable artwork URL,
   restore it and request again; verify it is not stuck in-flight. Exercise
   cancel/back/next transitions and repeated covers.
5. Observe `/proc/meminfo`, process status and kernel logs before, during and
   after misses/hits while audio plays. Capture measurements on the workstation,
   not by continuous writes to Radio flash. Some firmware reports zero/invalid
   RSS; record that limitation rather than treating it as zero memory usage.
6. Check for OOM messages, Jive restarts, audio underruns and UI stalls. Test a
   representative large raster carefully: a 2048² image can consume 12–16 MiB
   in Jive, even though the proxy streams it. Stop stress testing if playback or
   memory becomes unsafe; a resizer remains a separate measured decision.
7. Acceptance requires successful display/retry/SVG conversion, no retired
   proxy traffic, stable memory and uninterrupted audio. Do not infer those
   hardware results from QEMU or host tests.

## Remaining limitations

No decoded-memory bound is added to Jive's existing raster decoder. No automatic
raster resizing or preservation of Logitech's remote resizing quality is
promised. Existing HTTPS wrappers are upgraded only when they match the known
numeric-loopback proxy interface. Private SVG conversion is not enabled by
weakening the renderer's SSRF policy. MIME dispatch requires correct Content-Type
when there is no SVG extension. Independent custom applet loaders that bypass
the standard Jive pipeline can opt into the shared service but are not globally
intercepted. Firmware patch compatibility is source-verified, not assumed from
a version label.
